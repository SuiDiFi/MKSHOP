4. 请求链路、权限模型与接口登记

4.1 一条请求怎么走

浏览器 → nginx（PATHINFO 重写，SPA 禁缓存，uploads 禁执行）
       → public/index.php → think 路由（route/*.php，url_route_must=true）
       → 端中间件组 → 控制器（继承 mks\BaseController，多数 CRUD 直接混入 CurdTrait）
       → service / model → MySQL(mks_*) / Redis
       → ResponseTrait 统一 {code,msg,data,time}
端中间件链（实测自 route/*.php）
adminCors → 公开组 ｜ 鉴权组 AdminToken → AdminAuth → AdminLog（route/admin.php:296-301）
frontCors + VipSiteToken；登录子组加 MemberToken；3 条公开接口挂 MemberTokenOptional
vipMemberToken + VipOwnerAuth
merchantMemberToken（控制台子组再加 MerchantAuth）
api / dockapi / mp / mock / addons / h5仅 Cors（dockapi 的验签在服务层，不在中间件）
install / healthz无中间件（public/index.php 里放行）

4.2 后台权限判定顺序（这一层最容易踩）

isSuper ──► 直接放行（因此超管账号无法暴露登记缺失）
   ↓ 否
mks_api_permission 显式白名单 ──► 命中即放行（Redis 缓存 60s，AdminAuth.php:106-118）
   ↓ 未命中
mks_admin_router 中 auth_type=2 的接口登记 ──► RESTful 尾巴 /\d+ 剥掉后匹配 api_url + methods
   ↓ 未登记
403（默认拒绝）
   ↓ 命中
角色授权：admin_role.role 里的路由 id 集合是否包含该行
新增任何后端接口，必须同时做两件事，否则普通角色必 403：① 在 mks_admin_router 插一行 auth_type=2 的接口登记（幂等迁移写法参照 deploy/sql/mks_m8e.sql，它补的就是 goods/create，线上行 id 662）；② 在「角色管理」里把该权限点勾给角色——登记 ≠ 授权，两件事常被混为一谈。

9. 验收与取证方法

9.1 浏览器量测的三条硬规则（本轮踩坑实录）

  • 后台标签页会产生假故障，但整页 reload 就能治：标签页不可见时 requestAnimationFrame 不派发，mode="out-in" 的路由过渡卡在 fade-transform-leave-*，新视图根本没插进 DOM（document.title 已更新、rows:0、量测全 null）。解法是 navigate_page(type:"reload") 重载目标 URL——首屏没有离场过渡，隐藏标签页里 40 行照渲染、getComputedStyle/getBoundingClientRect 照有效（§10.5 基线就是这么量的），不必麻烦人把标签页切前台。别用 hash/菜单切换去量。判据：DOM 里出现 fade-transform-leave-active ＝ 卡住了。
  • el-upload 的 file input 是 display:none，按 uid 点不到它。要造 File：new DataTransfer(); dt.items.add(new File(...)); input.files = dt.files; input.dispatchEvent(new Event('change',{bubbles:true}))，走组件自己的 http-request。
  • visibility:hidden 的元素 innerText 为空，判断存在性用 textContent；display:none 的下拉菜单本身就在 DOM 里，取证「更多」菜单项不必点开（生产站也不该乱点）。
  • 站点连不上先怀疑本机代理：本机 HTTPS_PROXY=http://127.0.0.1:7897 对 mksup.top 会 TLS 握手失败（浏览器 ERR_CONNECTION_CLOSED、http 侧 502），而服务器侧与 curl --noproxy '*' 都是 200。别把代理问题当成站点故障去重启服务。
  • 别用「第一个 .el-tabs / .el-table」定位：这两套后台的左侧菜单本身也是一组 el-tabs（参考后台那组有 29 项），取 [0] 会量到它，于是产生过「状态页签 active 无下划线」这种错结论（详见 §10.6 的量测纪律框）。正确做法：先用页面专属文案（如「全部商品」）匹配文本节点，再向上 closest() 找容器。
  • 用无 token 的 curl 区分三类故障：404 ＝ 路由没注册；401 ＝ 路由在、没带登录态；403 ＝ 有登录态但权限点没登记/没授权。在服务器上直接 curl -s -o /dev/null -w '%{http_code}' -X POST 'https://mksup.top/index.php?s=/admin/xxx'，不需要造 token（也不该造）。

9.2 抓请求

页面内猴补丁 XMLHttpRequest 到 window.__log（open 记 method/url，loadend 记 status），即可读出「点了什么、发了几个请求」。注意：SPA 重新加载后钩子必须重装。负面结论：navigate_page 的 initScript 参数（本想用它预置钩子或给 requestAnimationFrame 打 setTimeout 兜底）实测返回 Script not found，别在这条路上耗时间——预置不了就直接 reload 之后用 evaluate_script 装。
