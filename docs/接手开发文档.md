## 5. 红线（违反会直接出事）

1. **生产库 SQL、部署、`git push` 三类动作必须用户点名授权**后才能执行；不确定就问，别「顺手」做。
2. **参考后台 `gl.monkm.cn/airuan` 是别人在用的生产站**：只点读态，不点任何「保存/确认/撤销」，不提交表单，不触发写接口。
3. **php-fpm 是 uid 82，`docker exec` 默认 root**。用 root 跑 CLI 会新建 root 属主的日志/缓存，web 进程随即写不进日志 → 表现为「500 但日志空白」。本轮就是这么把 `Upload` 异常藏住的（事后 `chown 82:82`）。跑过 CLI 收尾必查 `runtime/`、`public/uploads/` 属主。
4. **字段诚实**：表单只放后端真读的列。白名单里没人读的列（`only_balance`、`is_batch`、`is_recharge`、`goods_tags`、`check_content`、`stop_reason`、`demo_url`、`can_level`、`can_no_buy`、`take_up_time`）不放；只做前台显示的（`can_back`、`goods_name_color`）要在 UI 上写明。
5. **不提交**：`admin-web/dist` 等产物、`deploy/tmp_*.php`、任何凭据。服务器凭据只在 `H:\文档\MKSHOP服务器.txt`，只读、不抄进对话或文件。
6. **测试数据**：只用显式命名的临时对象（如「验收商品-xxx」），测完 `delete → destroy` 再物理核对，并清掉自己造的上传文件与 `mks_file` 行；真实数据（如商品 21）只读。
7. 提交信息沿用仓库风格：`feat(m8-ui): …` / `fix(m8-ui): …`，中文，说清「为什么」。
8. **git 命令前先 `git rev-parse --show-toplevel`**：本机 `C:\` 是个零提交的历史遗留仓（分支名就叫 `master`，见 §8），只有在 `H:/MKSHOP/mkshop` 下跑才作用于本项目；真实分支只有 `main`（默认）与 `develop`，**没有 `master`**，`git push -u origin master` 这类命令本身就是错误信号。

## 7. 验收与量测方法（本轮踩坑实录）

* **隐藏标签页能量测，但必须整页 reload**：标签页在后台时 `requestAnimationFrame` 不派发，Vue 路由过渡（`mode="out-in"`）卡在 `fade-transform-leave-*`，新视图根本没插进 DOM —— 表现是 `document.title` 已变、`rows:0`、量测全 `null`。**用 hash/菜单切换就会踩这个坑；直接 `navigate_page(type:"reload")` 重载同一 URL 则首屏没有离场过渡，40 行照常渲染、`getComputedStyle` 与 `getBoundingClientRect` 全部有效**（本轮页面级基线就是这么量到的，不需要把标签页切到前台）。DOM 里若看到 `fade-transform-leave-active` 就是卡住了，重载即可。
* **`mksup.top` 走不通先怀疑本机代理，别怀疑站点**：浏览器与 curl 都吃 `HTTPS_PROXY=http://127.0.0.1:7897`，该代理对 `mksup.top` 会 TLS 握手失败（浏览器 `ERR_CONNECTION_CLOSED`、http 侧 502）；判定方法是 `curl --noproxy '*' https://mksup.top/admin-web/` 与服务器侧 `curl https://mksup.top/admin-web/`（都返回 200 就是代理规则问题）。站点侧真相：宿主 nginx 监听 `:80/:443`，`mkshop-nginx` 容器发布在 `:8080`，另有 `mkshopz-*` 一套同名并行栈无发布端口。
* **`el-upload` 的 file input 是 `display:none`**，按 uid 点不到；要 `new DataTransfer(); dt.items.add(new File(...)); input.files = dt.files;` 再派发 `change`，走组件自己的 `http-request`。
* **`visibility:hidden` 的元素 `innerText` 为空**，判断存在性用 `textContent`。
* 抓请求：页面内猴补丁 `XMLHttpRequest` 记到 `window.__log`（`open` 存 method/url，`loadend` 存 status）；**SPA 重载后钩子要重装**。`navigate_page` 的 `initScript` 实测报 `Script not found`，预置不了，只能 reload 后再 `evaluate_script` 装。
* **量测「取第一个 `.el-tabs`/`.el-table`」会量错容器**：参考后台左侧菜单本身也是一组 `el-tabs`（29 项），第一个匹配到的就是它 → 于是把「激活态无下划线」写成了结论，实际商品页签有 2px `#1890FF` active-bar。**口径：先用页面专属文案（「全部商品」）定位，再向上找容器**；`document.querySelectorAll('.el-tabs')[0]` 这类写法在本项目一律不可信。
* **区分「路由没注册」和「权限没给」用无 token curl**：已注册未登录 → **401**；未注册 → **404「接口不存在」**；权限点缺失（普通角色）→ **403**。这三个码是 §6 三件套的体检探针，服务器上直接 `curl -s -o /dev/null -w '%{http_code}' -X POST 'https://mksup.top/index.php?s=/admin/xxx'` 即可，不需要登录态。
* 本轮商品载体实测（可复现）：进 `/goods/add` 7 个枚举 POST；下一步 ×5 每次 0 请求；空名称保存 → 「请完善数据」+ 跳回基本信息 + 0 写请求；上传 200 → `/uploads/goods/YYYYMMDD/*.png`；`create → delete → destroy` 往返全 200。
