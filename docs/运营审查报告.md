## 3. 做对了的部分（请接手者不要重写）

这些是经过读代码 + 线上行为双重确认的成熟点，重写只会引入新 bug：

1. **资金口径正确**：金额列 `decimal(16,4)`，运算走 bcmath；`MemberMoneyService::changeMoney()`（`app/common/service/MemberMoneyService.php:27-85`）事务 + `SELECT ... FOR UPDATE` 行锁 + 余额不足拒绝 + before/after 快照流水 + 失败回滚。
2. **密码存储正确**：管理员与会员均 `password_hash(PASSWORD_BCRYPT)` / `password_verify`，没有 md5/sha1 存密码。
3. **订单/支付/退款大量采用条件状态更新**（`where('status', 旧值)->update(...)` 并判断 affected rows），具备基本的幂等意识；自动发货失败**不回滚支付**，订单落人工处理并写日志——这是正确的取舍。
4. **卡密 FIFO 发货在事务内锁卡**（`OrderService.php:398-417`：`status=1 AND order_id=0` + `lock(true)`），退款时卡密置 `status=3` 冻结**不回库**，从机制上防二次售卖（`OrderService.php:596`）。
5. **安装向导有锁**：`POST /install/run` 实测 403「系统已安装」；`mockv2` 对接模拟端点要求签名头，未授权直接 400。
6. **上传第一道防线有效**：扩展名白名单（`mks/util/Upload.php:22-27`），不含 php；文件名 `bin2hex(random_bytes(16))`（`Upload.php:42`），不可猜测、无目录穿越。
7. **路由与权限点有静态自检**：`tools/check_api_routes.mjs` 当前结果 296 条后端路由 / 195 处前端调用 / 缺注册 0 / 缺权限点登记 0。
8. **JWT 有服务端失效能力**：token 对应服务端缓存键 `token:{scene}:{jti}`，可主动踢下线；密钥未配置会直接抛错而非静默用空密钥。
9. **SQL 注入抽查安全**：几处 `whereRaw("FIND_IN_SET({$id}, ...)")` 的入参均为 `int` 类型声明或 `(int)` 强转。

### 5.3 支付 Redis 锁用裸 `del` 释放，可能误删他人锁 —— ✅ 已处置（2026-11-19）【静态→已修】

## 8. 给下一个助手的硬约束（摘自长期记忆，仍是红线）

1. 部署、推送、生产 SQL 必须**用户逐次点名授权**；生产只读巡检可自由做。
2. 凭据只从权威来源逐字读取，不打印、不提交、不写入任何文档；不用 `curl -k`。SSH 凭据：`H:\文档\MKSHOP服务器.txt`；**MySQL/Redis 凭据（2026-11-17 轮换后）：服务器 `/root/.mkshop-credentials`（600）**，脚本里用 `sed -n 's/^KEY=//p'` 取值后注入 `MYSQL_PWD` / `redis-cli -a`，不回显。
3. 远程操作只走 `node tools/ssh_put.mjs` / `node tools/ssh_run.mjs -f`，复杂命令写成脚本上传执行；`docker exec -w` 只用容器路径 `/var/www/mkshop`。
4. 生产 SQL 前先 dump 受影响表到 `/root/mks_<table>.bak-<ts>.sql`；查中文加 `--default-character-set=utf8mb4`。
5. `docker exec` 是 root、php-fpm 是 uid 82：跑完 CLI 检查 `runtime/log` 属主，必要时 `chown -R 82:82 runtime public/uploads`。
6. 测试只用名字明显的自造数据并事后清理；真实商品 id 21 只读；不动真实会员与真实订单。
7. 任何"已完成"都要有本轮磁盘/命令证据；**本地已提交 ≠ 线上已生效**，分开陈述。
8. KASUSHOU 参考后台只读；浏览器验收由用户人工登录。
9. **禁止用仓库 `docker-compose.dev.yml` 覆盖 `/opt/mkshop/docker-compose.dev.yml`**：生产版已加固（端口绑 `127.0.0.1`、强口令、`requirepass`、healthcheck 读 env），覆盖会同时恢复公网暴露并使 `.env` 口令失配导致站点 500。上传部署前先 `md5sum` 比对，生产版当前为 `79a527fd410648e781629a683845c272`。
10. **改 MySQL/Redis 凭据必须三处同步**：服务器账号本体（`ALTER USER` / `requirepass`）、`/opt/mkshop/.env`、`/root/.mkshop-credentials`；改完必须重启 `php` 与 `queue`（`queue:listen` 是长驻进程，不会自动重读 `.env`），并等一轮 `mks:timer` cron 确认。`MYSQL_ROOT_PASSWORD` 这个 compose 环境变量**只在数据目录为空时初始化生效**，对已有库改口令必须走 `ALTER USER`。
11. **从 Windows 部署 shell 脚本必须是 LF**：`core.autocrlf=true` 会把工作副本转成 CRLF，上传后 dash 把 `\r` 当参数的一部分而解析失败。仓库已加 `.gitattributes`（`*.sh text eol=lf`）从根上固定；上传前仍应复核 `tr -cd '\r' < 文件 | wc -c` 为 0。另：`ssh_put.mjs` 的远程目录参数在 Git Bash 下会被 MSYS 改写成 `C:/Program Files/Git/...`，需带 `MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'`。
12. **服务器 `/bin/sh` 是 dash**：没有 `pipefail`、没有 `PIPESTATUS`、没有 `[[ ]]`。写 `#!/bin/sh` 脚本时，`cmd1 | cmd2` 的退出码只反映 `cmd2`——凡是"失败必须被发现"的管道都要拆两步判退出码。校验语法用服务器上的 `dash -n`，本地 Git Bash 的 `sh -n` 查不出 dash 特有问题。
13. **`docker exec` 不带 `-i` 就不转发 stdin**：`docker exec … mysql … < query.sql` 会静默得到空结果。推广成一条通用纪律：**任何"两边一致"的比对，先证明两边非空**，否则空对空会假通过（本轮演练脚本差点踩这个）。
14. **生产演练只碰隔离库**：库名必须以 `mks_restore_` 开头且不等于业务库；目标库已存在就拒绝执行而不是删掉它；演练脚本不得调用 `restore.sh`（它会 `FLUSHDB` 清生产缓存）。行数比对要用逐表真 `COUNT(*)`，`information_schema.table_rows` 对 InnoDB 是估算值，不能当验收依据。
15. **ThinkPHP 控制台渲染异常后仍以 0 退出**：`php think …` 或引导了框架的探针脚本抛异常时，会把异常渲染成方框文本然后 **exit 0**。所以 shell 里 `$?`、`set -e`、`|| exit 1` 全都拦不住它——本轮验收编排一度把 5 次连接失败全报成 `exit=0`。**判定成败一律 grep 自己打印的结束标记**（如 `VERIFY_PASS` / `RACE_PASS`），退出码只作参考。
16. **升级器失败的文件不会自动重试**：`mks:upgrade` 把 `fail` 也写进 `mks_schema_version`，而待执行清单只按 `version` 过滤、**不看 `status`**（`app/common/commands/Upgrade.php:49-56`）。所以迁移失败后直接重跑会显示"没有待执行的升级脚本"。必须先 `DELETE FROM mks_schema_version WHERE version='<文件名>' AND status='fail';` 再重跑。错误提示里"修复后重跑"这句话是**不准确的**。
17. **别为跑探针去放宽数据库权限**：P0-1 之后应用账号 `mkshop` 只有 `mkshop.*` 权限、`root` 只剩 `root@localhost`（socket），因此**容器内的 PHP 探针连不上任何 `mks_restore_*` 隔离库**（实测 `1044 Access denied`，换 root 则 `1045`）。正确做法是按红线 6 在业务库用明显前缀的自造数据验收 + 跑完清理 + 真实计数前后比对，**不是** `GRANT` 一个临时权限或新建账号。另：容器是 Alpine/BusyBox，`diff` 没有 `--strip-trailing-cr`，要比对行尾不同的文件请在宿主上用 GNU diff（`/opt/mkshop` 是 bind mount）。
